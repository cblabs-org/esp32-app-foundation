# Custom Boot Branding & System Screens Guide

This guide explains how downstream applications can customize boot branding (application title and boot splash logo) and override built-in system screens (error, OTA progress, configuration wizard) in ESP32 App Foundation applications.

---

## Architecture Overview

ESP32 App Foundation supports optional custom boot branding and pluggable system screen providers across both supported display engines: **U8G2** (monochrome OLED/LCD) and **LVGL** (color TFT/touch).

Both display modules share a uniform opt-in dependency injection model via their constructor parameters:

```cpp
// U8G2 Display Module
explicit U8G2DisplayModule(const BootBranding* branding = nullptr,
                           const U8G2BootLogo* bootLogo = nullptr,
                           IU8G2SystemScreens* screens = nullptr);

// LVGL Display Module
explicit LVGLDisplayModule(ILVGLHardwareAdapter& adapter,
                           const BootBranding* branding = nullptr,
                           const lv_image_dsc_t* bootLogo = nullptr);
```

If no custom parameters are supplied (`nullptr`), the framework falls back to defaults:
- **Application Title:** Defaults to the `"ESP32 App Foundation"` string (or `APP_TITLE` macro definition if set at compile time).
- **Boot Logo:** Defaults to the built-in CB Labs logo.

---

## 1. Application Title (`BootBranding`)

The `BootBranding` struct is a lightweight, display-agnostic descriptor that provides the application title displayed on boot screens and system header overlays.

### Definition (`include/types/BootBranding.h`)

```cpp
struct BootBranding {
    const char* appTitle = nullptr;   ///< Application title string (nullptr = default "ESP32 App Foundation")
};
```

### Basic Usage

Define a `constexpr` instance of `BootBranding` at file scope or in `main.cpp` and pass its address to the display module:

```cpp
#include <types/BootBranding.h>

static constexpr BootBranding myBranding{
    .appTitle = "My Custom Product"
};

// Injection into U8G2DisplayModule:
U8G2DisplayModule displayModule(&myBranding);

// Injection into LVGLDisplayModule:
LVGLDisplayModule displayModule(hardwareAdapter, &myBranding);
```

## 2. Boot Splash Logo

### Critical Boot Timing Constraint

> [!IMPORTANT]
> **Compile-Time C-Arrays Required:** Phase 1 boot splash rendering occurs during early hardware bootstrap (`bootstrapHardware()`), **before** LittleFS or SPIFFS filesystem mounting and before network services start.
> Therefore, boot splash logos **MUST** be compile-time C-arrays baked into flash (`PROGMEM`), and cannot be loaded from filesystem paths or URLs.

### U8G2 Boot Logo (`U8G2BootLogo`)

U8G2 uses monochrome XBM byte arrays. Define a `U8G2BootLogo` struct pointing to the XBM pixel array:

#### Descriptor Definition (`modules/U8G2Display/U8G2BootLogo.h`)

```cpp
struct U8G2BootLogo {
    uint16_t width;
    uint16_t height;
    const uint8_t* bits;    ///< Pointer to XBM byte array in flash
};
```

#### Example Usage

1. Create or export an XBM image (e.g. `my_logo_xbm.h`):

```cpp
// my_logo_xbm.h
#pragma once
#include <cstdint>

#define my_logo_width 48
#define my_logo_height 48
static const uint8_t my_logo_bits[] PROGMEM = {
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00,
    // ... XBM byte data ...
};
```

2. Wrap the logo in a `U8G2BootLogo` descriptor and pass it to `U8G2DisplayModule`:

```cpp
#include "my_logo_xbm.h"
#include <U8G2Display/U8G2BootLogo.h>
#include <types/BootBranding.h>

static constexpr U8G2BootLogo myLogo{
    .width = my_logo_width,
    .height = my_logo_height,
    .bits = my_logo_bits
};

static constexpr BootBranding myBranding{"My Product"};

U8G2DisplayModule displayModule(&myBranding, &myLogo);
```

### LVGL Boot Logo (`lv_image_dsc_t`)

LVGL v9 uses C-array image descriptors (`lv_image_dsc_t`) generated by the LVGL Image Converter tool.

#### Example Usage

1. Convert your logo (PNG/SVG) to an LVGL C array (e.g. `my_lvgl_logo.c` / `my_lvgl_logo.h`):

```c
// my_lvgl_logo.h
#pragma once
#include "lvgl.h"

extern const lv_image_dsc_t my_lvgl_logo;
```

2. Pass the image descriptor pointer to `LVGLDisplayModule`:

```cpp
#include "my_lvgl_logo.h"
#include <types/BootBranding.h>

static constexpr BootBranding myBranding{"My Product"};

LVGLDisplayModule displayModule(hardwareAdapter, &myBranding, &my_lvgl_logo);
```

## 3. Custom System Screens Provider Pattern

Applications can override the framework's built-in system screens (such as Error, OTA Progress, WiFi Wizard, or Configuring screens) by implementing a custom system screens provider interface.

### U8G2 System Screens (`IU8G2SystemScreens`)

#### Interface (`modules/U8G2Display/IU8G2SystemScreens.hpp`)

```cpp
class IU8G2SystemScreens {
public:
    virtual ~IU8G2SystemScreens() = default;

    /// Custom error board, or nullptr for built-in ErrorBoard
    virtual IDisplayBoard* errorBoard()        { return nullptr; }

    /// Custom OTA progress board, or nullptr for built-in OTAProgressBoard
    virtual IDisplayBoard* otaProgressBoard()  { return nullptr; }

    /// Custom configuring board, or nullptr for built-in ConfiguringStatusBoard
    virtual IDisplayBoard* configuringBoard()  { return nullptr; }

    /// Custom WiFi wizard board, or nullptr for built-in WiFiWizardBoard
    virtual IDisplayBoard* wifiWizardBoard()   { return nullptr; }
};
```

#### Example Implementation

```cpp
#include <U8G2Display/IU8G2SystemScreens.hpp>
#include <U8G2Display/IDisplayBoard.hpp>

class CustomErrorBoard : public IDisplayBoard {
public:
    void render(U8G2& u8g2) override {
        u8g2.setFont(u8g2_font_6x10_tf);
        u8g2.drawStr(10, 20, "CUSTOM ERROR SCREEN");
    }
    bool isExpired() const override { return false; }
    const char* getBoardName() const override { return "Custom Error"; }
};

class CustomSystemScreens : public IU8G2SystemScreens {
public:
    IDisplayBoard* errorBoard() override {
        return &_customErrorBoard;
    }
    // Returning nullptr for other methods falls back to framework defaults

private:
    CustomErrorBoard _customErrorBoard;
};

// Instantiation & Injection
static constexpr BootBranding myBranding{"My Product"};
static CustomSystemScreens mySystemScreens;
U8G2DisplayModule displayModule(&myBranding, nullptr, &mySystemScreens);
```

### LVGL Pro UI Customisation

The LVGL display no longer uses an `ILVGLSystemScreens` adapter interface.
Instead, the framework communicates with the UI design through **reactive subjects**
(`sys_*`). The UI design is an LVGL Pro Editor project living in
`uidesign/<environment>/lvglpro/` and packaged as a PlatformIO library via `library.json`.

#### How Consumers Extend the UI

1. **Fork the framework's design folder** into your application repository
   (e.g. `src/ui/lvglpro/` or `uidesign/<your-env>/lvglpro/`)
2. **Override `lib_extra_dirs`** in your `platformio.ini` to point to your design folder
   instead of the framework's
3. **Preserve the 23 `sys_*` subjects** — the framework contract requires these names
   to exist in `globals.xml`. Do not rename or remove them.
4. **Add application subjects** with an `app_*` prefix (e.g. `app_temperature`,
   `app_zone_name`) to avoid collisions
5. **Add custom screens** — create additional `screen_*.xml` files for app-specific
   screens (e.g. thermostat control, dashboard)
6. **Override the RUNNING transition** — your display module loads your app screen
   instead of the default `_diagScreen`

#### Example: Consumer `platformio.ini`

```ini
[env:my-product]
lib_extra_dirs =
    esp32-app-foundation/modules
    esp32-app-foundation/adapters
    src/ui    ; Consumer's LVGL Pro design overrides framework default
```

#### Example: Consumer `main.cpp`

```cpp
#include <LVGLDisplay/LVGLDisplayModule.hpp>
#include <MyAdapter.hpp>

static BootBranding branding = { .appTitle = "My Product" };
static MyAdapter adapter;
static LVGLDisplayModule displayModule(adapter, &branding, &my_logo);
```

---

## Summary Checklist for Board / App Customization

1. Create a `BootBranding` struct for your product title.
2. Prepare an XBM array (U8G2) or `lv_image_dsc_t` (LVGL) for the boot splash logo in `PROGMEM`.
3. For U8G2: optionally subclass `IU8G2SystemScreens` if overriding default system screens.
4. For LVGL: fork the LVGL Pro design folder, preserve `sys_*` subjects, add `app_*` subjects.
5. Pass branding and logo pointers into the display module constructor in your `main.cpp`.
