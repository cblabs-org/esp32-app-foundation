# ADR: Portal JS Split Pattern + WebServerManager Registration Requirement

## Decision

Each top-level or sub-pill tab gets its own JS fragment file. Every new JS file MUST be registered in `WebServerManager.cpp` with both a `#include` and a `_server.on()` route handler.

## Context

`appconfig.js` originally contained all display hardware controls (brightness, flip, screensaver) alongside app-level config (clock font size). When the Display module gained its own `"Display"` tab with a `"Settings"` sub-pill, the hardware controls were extracted to `display.js`.

## Registration Requirement (CRITICAL)

**Every portal JS file must have three things:**
1. A source file in `web/portal/`
2. An `#include "portal_assets/xxx_js.hpp"` in `WebServerManager.cpp` (lines 33–47)
3. A `_server.on("/xxx.js", HTTP_GET, [...])` route handler in `WebServerManager::begin()`

The HPP headers are auto-generated by the `build_portal_assets.py` script run as a pre-build step. They are **gitignored** (`include/portal_assets/` is in `.gitignore`).

**`display.js` was initially missing steps 2 and 3.** This caused a silent browser 404 when `app.js` loaded it via `loadScripts()`. The browser continued without error, so the `tab-changed → 'tab-settings'` listener was never registered, and the Settings pill showed empty. See `graveyard_webserver_route_miss.md`.

## JS Fragment Architecture

| File | Tab target | Event listened to |
|------|-----------|-------------------|
| `wifi.js` | `#tab-wifi` | `tab-changed: 'tab-wifi'` |
| `display.js` | `#tab-settings` | `tab-changed: 'tab-settings'` |
| `screenshot.js` | `#tab-screenshot` | `tab-changed: 'tab-screenshot'` (also auto-captures on entry) |
| `appconfig.js` | `#tab-app` | `tab-changed: 'tab-app'` |
| `system.js` | `#tab-status` | `tab-changed: 'tab-status'` |

## Script Load Order in `app.js`

```javascript
loadScripts([
  'utils.js', 'wifi.js', 'system.js', 'time.js', 'backup.js',
  'ota.js', 'keys.js', 'mcp.js', 'screenshot.js',
  'display.js',     // ← inserted in PR-23 (before appconfig.js)
  'appconfig.js'
]);
```

Scripts load before `loadTabs()` — so `tab-changed` listeners are always registered before the first tab activation fires.
