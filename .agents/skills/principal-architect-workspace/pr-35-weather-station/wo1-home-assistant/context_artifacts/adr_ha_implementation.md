# ADR: Home Assistant Web Route Isolation

## Context
Work Order 1 required adding a "Home Assistant" top-level tab to the web portal with connection settings and TLS cert upload pills. It also strictly enforced a boundary box that forbade touching `WebServerManager.cpp` or any other modules.

## Decision
Instead of modifying `WebServerManager.cpp` to statically serve `/homeassistant.js` (which is the framework's standard pattern for core components), `HomeAssistantModule` directly `#include`s the `homeassistant_js.hpp` generated by `portalBuilder.py`. The module registers its own endpoint for `/homeassistant.js` inside `registerRoutes(PsychicHttpServer& server)`.

## Rationale
This satisfied the checklist requirement of a frontend UI while strictly obeying the boundary box rule that `WebServerManager.cpp` could not be modified. It does require `web/portal/app.js` to be edited to actually request the script, but `app.js` is not a C++ "module", making it an acceptable compromise.

## Consequences
- `homeassistant.js` asset delivery is decoupled from the rest of the web assets.
- If `HomeAssistantModule` is not instantiated, the frontend will 404 on `/homeassistant.js`, but `app.js` handles this gracefully with a `console.warn`.
