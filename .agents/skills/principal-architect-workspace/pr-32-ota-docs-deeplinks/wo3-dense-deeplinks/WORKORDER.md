# Work Order: Dense Deep Links in Design Specification

You are an expert senior software engineer and technical writer. You are NOT the Principal Architect.

## Objective

The design specification currently has 17 deep links at the `##` (major section) level only. This is not enough — the user wants links at the `###` subsection level too. Every subsection that has a corresponding topic in the developer guides should have an inline link.

The goal: a reader browsing any part of the design spec can immediately jump to the hands-on tutorial covering that exact topic.

- **DO** modify ONLY `docs/design_specification.md`

## Strategy

### Link Format

For subsection-level links, use a compact **inline** format (not a callout box — those are too heavy for every subsection). Place the link as a single line immediately after the `###` heading:

```markdown
### 6.2 `ITickable`

> 📖 See [Creating a Module § The Tick Loop](developer/creating-a-module.md#3-implementing-the-module-logic) for implementation tutorial.
```

For sections that ALREADY have a `📖 **Developer Guide:**` callout from the previous pass (17 exist at the `##` level), KEEP those as-is and add subsection links below them as needed.

### Anchor Name Convention

GitHub-flavoured Markdown anchors are generated by:
1. Lowercasing the heading text
2. Removing punctuation except hyphens
3. Replacing spaces with hyphens
4. Example: `## 7. The Application Lifecycle` → `#7-the-application-lifecycle`

Read each developer guide's headings to determine exact anchor names. When in doubt, link to the file without an anchor rather than guessing a broken anchor.
