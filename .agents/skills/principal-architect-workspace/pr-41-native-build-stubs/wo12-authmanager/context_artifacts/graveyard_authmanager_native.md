# Graveyard: AuthManager Native Stubs

## Failed Attempt 1: Empty mbedTLS md functions
**What we tried:** Initially, `test/stubs/platform/mbedtls/md.h` contained empty macros/functions returning `0` for `mbedtls_md_update` and `mbedtls_md_finish`. 
**Why it failed:** Several tests (`test_verify_password_wrong`, `test_mcp_bearer_equals_hash`) rely on actually hashing passwords correctly to verify negative and positive logic. Returning `0` with an empty hash buffer caused these tests to fail.
**Resolution:** Re-introduced a portable C++ SHA-256 implementation inside the `md.h` stub to satisfy native tests.

## Failed Attempt 2: Incorrect Test Mock File Paths
**What we tried:** To make `test_load_cert_fails_without_files` fail loading, we called `LittleFS.remove("/ssl/cert.der")` and `LittleFS.remove("/ssl/key.der")`.
**Why it failed:** AuthManager writes and reads from `/etc/server.crt` and `/etc/server.key` (a path that changed earlier in development). Because the test removed the wrong files, the legacy files generated by the preceding test (`test_generate_cert_sets_flag`) remained on disk. `loadCert` succeeded, failing the test.
**Resolution:** Updated `LittleFS.remove` arguments in the test to use the correct `/etc/server.crt` and `/etc/server.key` paths.

## SIGHUP on Exit
**Observation:** Native test runs often reported a `SIGHUP` or `ERRORED` status when tests exited or aborted abruptly due to uncaught assertions or pointer issues in the custom hashing stubs. 
**Resolution:** By properly managing the context structs and deleting the generated LittleFS test files correctly, the `SIGHUP` crash was resolved entirely.
