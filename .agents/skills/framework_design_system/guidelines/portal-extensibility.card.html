The portal ships only mandatory tabs (WiFi, System, Security). Every other tab is an optional module that contributes itself at runtime — which is why the UI kit hard-codes only the core few.

1A module implements IWebContributor and registers a tab (id, label, icon path) via /api/tabs. 2The shell renders the bottom-nav entry and fires tab-changed when selected. 3The module's fragment JS listens for that event and injects its markup into the shared container #tab-content. 4Feedback follows the 4-tier save policy: silent · showToast() · inline alert · showRebootOverlay().

Build new tabs from the templates/module-tab/ skeleton so they inherit the tokens, ID-prefixing and feedback conventions. See framework-expert/systems/web-portal.
