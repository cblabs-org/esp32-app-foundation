# PR-24 WO12 — Fix ERR_CERT_INVALID & Advanced TLS Settings

## Context
1. **Chrome ERR_CERT_INVALID:** The self-signed certificate generated by `mbedtls` currently lacks the `Subject Alternative Name (SAN)` extension. Modern Chrome strictly requires this and throws an un-bypassable error without it.
2. **Advanced Certificate Management:** The user wants the ability to force-regenerate the certificate, manually upload a CA-signed PEM certificate, and enable TLS for the Captive Portal.

## Objective
Fix the certificate generator to inject a valid SAN extension, and build the "Advanced TLS Settings" UI in the portal to allow certificate uploading and AP Mode TLS toggling.

## Execution Checklist

- `[x]` **Fix Certificate SAN (`AuthManager.cpp`)**
  - In `generateAndStoreCert()`, add the `X509v3 Subject Alternative Name` extension.
  - You must construct an ASN.1 sequence containing both the mDNS hostname (`DNS:esp32-device.local`) and the current IP address (`IP:192.168.x.x` if available from `WifiManager`).
  - *Hint:* Use `mbedtls_x509write_crt_set_subject_alternative_name` if available, or build the `MBEDTLS_OID_SUBJECT_ALT_NAME` raw extension using `mbedtls_x509write_crt_set_extension`.

- `[x]` **Backend Updates (`AuthManager.cpp / .hpp`)**
  - Add `tls_ap_mode` boolean to the `AuthManager` JSON configuration schema (default `false`).
  - Implement `POST /api/auth/cert/generate` -> calls `generateAndStoreCert()` and responds `{ "status": "ok", "restartRequired": true }`.
  - Implement `POST /api/auth/cert/upload` -> accepts `{ "cert_der": "base64...", "key_der": "base64..." }`. Decode the base64, save directly to `KeyManager`, and set `_certPresent = true`.
  - Implement `POST /api/auth/config` -> accepts `{ "tls_ap_mode": true/false }`, saves config, and responds `{ "status": "ok", "restartRequired": true }`.
  - Update `GET /api/auth/status` to return `tlsApMode: true/false`.

- `[x]` **Update TLS Boot Guard (`WebServerManager.cpp`)**
  - Update `WebServerManager::tick()` so `useTls` is evaluated as:
    `if ((!apMode || _authManager->isApTlsEnabled()) && ...)`

- `[x]` **Frontend Advanced Settings UI (`web/portal/auth.js`)**
  - Add an "Advanced Settings" section below the "TLS Certificate" card.
  - **AP Mode TLS Checkbox:** Toggles the `tls_ap_mode` config via API.
  - **Regenerate Button:** Hits the `/generate` endpoint.
  - **Upload Form:** Two `<textarea>` elements (one for Cert PEM, one for Key PEM).
    - When "Upload" is clicked, Javascript must strip the `-----BEGIN...` and `-----END...` headers and all whitespace/newlines from the PEM text.
    - Convert the resulting Base64 string directly into a raw Base64 string (do not `atob` to an array, just send the cleaned Base64 payload itself if the backend base64 decodes, or just `atob` and send raw binary if you prefer. Using JSON `{ "cert_der": "base64..." }` with a backend base64 decoder like mbedtls's `mbedtls_base64_decode` is safest).
