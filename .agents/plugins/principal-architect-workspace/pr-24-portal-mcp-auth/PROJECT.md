## Objective

Add session-based authentication and self-signed TLS to the web portal and
bearer-token authentication to the MCP HTTP endpoint. A password without TLS
exposes the credential to LAN sniffing; both layers are delivered together.

**Protocol model:**
- AP mode OR no password set → HTTP port 80, no auth (status quo preserved)
- Password set → HTTPS port 443, session cookie auth; HTTP port 80 redirects

## Key Design Decisions

See [DESIGN.md](./DESIGN.md) for full rationale. Summary:

- **New module:** `AuthManager` — owns IConfigurable namespace `"auth"`, KeyManager
  entries `portal_password_hash` + `portal_password_salt`, LittleFS cert files
- **Crypto:** SHA-256 (password hash) + EC P-256 (TLS cert) via mbedTLS (already linked)
- **Auth mechanism:** Session cookie (portal), Bearer token (MCP HTTP)
- **TLS:** `AsyncWebServerSecure` on port 443; `AsyncWebServer` on port 80 for redirect
- **AP mode:** Always HTTP, always open — captive portal compatibility
- **No password set:** HTTP port 80, no auth — status quo preserved
- **Security tab:** Top-level bottom-nav tab with lock icon (not System sub-pill)
- **`getTabIcon()`:** New optional method on `IWebContributor` to declare SVG icon
